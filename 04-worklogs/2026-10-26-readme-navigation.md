# README와 공용 명세 탐색 구조 정리

## 목적

GitHub 방문자가 공용 명세의 역할·읽는 순서·도메인별 기준 문서를 찾을 수 있게 README를 정리한다.

## 수행 내용

- 조직명과 관련 저장소 링크를 Uplus-GETDDO 기준으로 통일했다.
- 오래된 파일 트리 대신 문서 책임과 도메인별 바로가기를 제공했다.
- API 계약의 채택·구현·배포·실측을 구분하고 개별 계약의 상태를 확인하도록 안내했다.
- 공용 명세 main 직접 반영과 코드 저장소 PR 규칙의 적용 범위를 구분했다.

## 확인한 사실

- 로컬 main과 origin/main이 같은 상태에서 작업을 시작했다.
- 협업 방식의 기준은 [AGENTS.md](../AGENTS.md)다.
- 요구사항·정책·API 계약 자체는 변경하지 않았다.

## 다음 작업과 미결정 사항

- FE·공용 명세 변경 문서 10개의 내부 링크·앵커 155개를 검사해 끊어진 참조가 없음을 확인했다.
- 변경 문서의 Prettier 검사와 두 저장소의 `git diff --check`를 통과했다.
- 위 검증 시점에는 커밋·원격 반영을 수행하지 않았다. 이후 사용자 요청에 따라 GD-362로 반영한다.
- 새로운 공용 정책 결정이나 API 변경은 없다.
- 프론트엔드의 README·캡처·검증 기록 색인 정리는 FE 저장소에서 관리한다.
