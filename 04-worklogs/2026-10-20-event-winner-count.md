# 작업 기록: 사용자 이벤트 목록의 당첨 예정 인원 합계

- 작성일: 2026-10-20 (KST)
- 관련 이슈: [GD-251](https://ureca4.atlassian.net/browse/GD-251)
- 상태: 검토 대기 — 담당자 확인 전
- 영향 범위: 프론트엔드 / 백엔드

## 목적

사용자 목록 카드의 당첨 인원 표시 요청을 공용 API 계약에 반영한다. 사용자 최종 결정에 따라 당첨 인원순 정렬, 태그·추천 기능은 제외한다.

## 한 일

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 목록 인원 | 상세의 경품별 인원만 있고 E01에는 없음 | EventSummary에 경품별 당첨 예정 인원 합계 `winnerCount:long` 추가 |
| 사용자 목록 요청·정렬 | 기존 필터·최신 등록순·페이지 형식 | 변경 없음. 인원순 정렬은 추가하지 않음 |
| 상세·관리자 | 경품별 인원 제공 | 기존 구조 유지. 새 목록 전용 합계는 추가하지 않음 |

## 확인된 내용

- 작업 시작 전에 spec main을 pull하고 기존 E01·AE01과 공통 페이지 계약을 확인했다.
- 사용자가 인원순 정렬의 사용 여부가 미정이므로 이번 범위에서 제외하고 합계 필드만 반영하도록 요청했다.
- 각 경품의 인원은 int지만 합계는 32비트 정수 범위를 넘을 수 있어 long으로 정의했다. 원래 경품 필수 정책이나 실제 당첨 결과 정책은 변경하지 않는다.
- 페이지 형식은 기존 `page`, `size`, `items`, `totalElements`를 유지한다.

## 다음 할 일

- BE 구현·테스트와 명세를 대조하고 FE가 새 목록 필드를 연결한다.

## 미결정·차단 사항

이번 확정 범위에 추가 정책 결정은 없다. 인원순 정렬과 태그·추천은 제외 범위이며 추후 사용을 전제로 구현하지 않는다.
