## 목적

관리자 화면에서 UUID만 보이는 불편을 줄이기 위해 기존 ID를 유지하고 현재 이름을 함께 제공하는 계약을 문서화한다.

## 한 일

- [공통 API](../05-api/common.md#관리자-응답의-사용자처리자-이름)에 이름의 출처·현재 이름 표시·ID 기반 식별·null·구현 예정 상태를 정리했다.
- [추첨](../05-api/drawing.md), [응모](../05-api/entry.md), [알림](../05-api/notification.md), [응모권](../05-api/ticket.md), [미션](../05-api/mission.md), [출석](../05-api/attendance.md)의 지정된 응답에 이름 필드를 반영했다.
- [ADR-028](../03-decisions/028-admin-user-display-names.md)으로 변경 전·후와 사용자 선택을 기록하고 목차에 연결했다.
- 일반 사용자 마스킹·설문 익명성·원본 추첨 스냅샷·감사 기록을 유지한다. 알림 작업 내부 커서에는 이름을 추가하지 않는다.

## 확인된 사실

- 기준 원격 스펙은 02ac9094d966b40e7ed24768458115280ac3580e, 백엔드 dev는 b90693c4다. 문서 반영 시점에 코드의 이름 필드 구현·배포가 완료됐다고 기록하지 않았다.
- 작업 복사본은 깨끗한 main에서 fast-forward한 뒤 수정했다. 기존 원본 저장소의 미커밋 문서는 수정하지 않았다.
- DB 컬럼·마이그레이션·백엔드 및 프론트엔드 코드는 수정하지 않았다. JOIN·일괄 조회 등 구현 방법은 공용 명세에 고정하지 않았다.

## 다음 할 일

- 담당자들이 API 계약을 검토하고 각 담당 코드에 조회·응답 변환·테스트를 반영한다.
- 프론트엔드는 응답 스키마와 표시를 갱신하고 ID에 의한 동일인 구분을 유지한다.
- 구현·리뷰·배포·프론트엔드 적용은 문서 게시와 별도로 확인한다.

## 미결정 사항

이번 요청의 이름 표시 방향은 사용자 승인 사항이다. 기존 기능의 미결정 업무 정책이나 보관 정책은 이번 작업에서 변경하지 않는다.

## 검증

문서만 변경했으므로 테스트·빌드는 실행하지 않았다. 변경 파일 11개의 상대 링크 137개와 앵커 49개, 이름 필드·타입·제외 범위 26개 조건을 검사했다. 기존 알림 도메인의 결과 발표 링크에서 잘못된 앵커 한 곳을 발견해 실제 제목인 `결과 발표 알림`으로 수정했다. 수정 후 링크·앵커·필드 대조와 `git diff --check`를 다시 확인했다.
