# GD-141 응모 요청 일시 차단 정책·AR01/AR02 계약 정리

- 날짜: 2026-10-21 KST
- 상태: 검토 대기 — Codex 작성, 담당자 확인 전

## 목적

사용자가 합의한 차단 정책과 조회 계약을 공용 스펙에 반영하고 내용에 직접적인 변경만 채팅에 diff 형태로 보고하도록 요청했다.

## 수행 내용과 확인된 사실

- [응모 규칙](../02-domain/entry.md#응모-요청-반복-초과에-따른-일시-차단--gd-141)에 정책을, [AR01/AR02](../05-api/abuse.md)에 조회 필드·타입·필터·정렬·권한과 evidence 예시를 반영했다.
- [구현 범위](../00-requirements/scope.md)와 [후속 항목](../00-requirements/pending-decisions.md#지급-전-차단-전환의-후속-확인)에서 이번 응모 자동 차단과 기존 지급 전 차단 후속을 구분했다. [ADR-027](../03-decisions/027-entry-request-temporary-blocking.md)은 제안 상태로 작성했다.
- BE origin/dev ddc3857f, spec origin/main d1b964d5를 읽기 전용으로 확인하고 spec main을 fetch했다. 기존 미커밋 작업 기록은 보존하고 pull·reset·stash는 하지 않았다. 수정 대상의 기존 내용과 원격을 대조했다. pending-decisions의 다른 도메인 관련 원격 변경은 이번 diff에 섞지 않았다.
- 기존 정책·데이터·사후 게임 계약을 임의 폐지하지 않았다. 기능 코드·ERD·Flyway·Jira·운영 배포는 변경하지 않는다. 문서 공유는 아래 별도 사용자 요청에 따라 진행한다.

## 검증과 미결정·후속

- 변경 문서 8개의 형식·추가 상대 링크·새 앵커·JSON 예시 검사와 git diff --check가 통과했다. 기존 미커밋 파일이 보존됐고 변경 범위가 관련 문서에 한정됨을 확인했다. 문서만 변경하므로 테스트·빌드는 실행하지 않았다.
- evidence의 객체 형태·근거 항목과 세부 JSON 필드명 초안을 구분했다. 세부 필드명·동시 기준 충족 시 대표 사유·관리자 권한/상세 없음 오류 번호는 후속이다.
- 저장 대기 자료구조·재시도 운영값·기존 검토 데이터 보존·새 마이그레이션은 BE 구현에서 검증한다. API 배포 일정·실제 Redis 설정·FE 통합 검증은 미확인이다.
- 사용자가 BE 설계·워크로그의 개별 PR 생성과 spec main push를 명시적으로 요청했다. 이번 문서 변경만 커밋한 뒤 최신 origin/main과 통합하고 일반 push한다. BE 설계와 일일 워크로그는 각각의 브랜치·PR에서 공유하며 구현 완료나 GD-141 전체 완료로 표시하지 않는다.
