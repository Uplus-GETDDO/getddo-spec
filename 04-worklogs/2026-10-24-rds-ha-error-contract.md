# 작업 기록: 운영 DB 연결 장애의 공통 503 계약 등록

- 작성일: 2026-10-24
- 관련 이슈 / PR: [GD-337](https://ureca4.atlassian.net/browse/GD-337) / [백엔드 PR #176](https://github.com/Uplus-GETDDO/getddo-be/pull/176)
- 상태: 검토 대기
- 영향 범위: 공통 오류 계약 / 백엔드 / 프론트엔드 오류 처리

## 목적

사용자가 지정한 백엔드 운영 DB 자동 전환 대응 실행 문서에 따라 연결 장애의 공통 503 계약을 원본 명세에 등록한다. 사용자가 검토용 패치를 확인하고 2026-10-24 명세 등록·커밋·push를 명시적으로 승인했다.

## 한 일

[공통 API 오류](../05-api/common.md#오류)에 COMMON-007과 공개 메시지, 기존 실패 봉투 유지, 연결 실패 범위, Retry-After 미추가 및 503과 저장 여부의 구분을 등록했다. 기존 업무별 멱등 기준과 다른 500·4xx·429 계약은 유지했다.

## 확인된 내용

- 변경 전 원격 spec main 6aa18edfad5e3e33cf0dd77cc4b80ac9bc3b184f, backend dev f588f201dfbb42c025426bdfe98196b384b66e7d와 main/실행 175cabb38cc564360c5618e5186de324f122336f에 COMMON-007 중복이 없었다.
- 백엔드 구현·단위 검증·PR 생성은 수행했으나 이 문서 등록 시점에는 필수 리뷰·CI·운영 배포를 완료로 간주하지 않는다.
- 프론트 변경과 운영 장애 시험은 제외했다. 화면 키 유지·안내 표시와 실제 failover 복구시간은 미검증이다.
- 기존 로컬 spec 미커밋 변경은 보존하고 최신 main의 별도 복사본에서 이 계약만 등록한다. spec의 main 직접 반영 규칙을 따르므로 추가 PR을 만들지 않는다.

## 미결정·차단 사항

운영 장애 응답 시간은 실측 없이 보장하지 않는다. 공용 명세의 기존 초안 전체를 확정으로 격상하지 않고 이 오류 계약만 사용자 실행 지시·등록 승인을 근거로 기록한다.
