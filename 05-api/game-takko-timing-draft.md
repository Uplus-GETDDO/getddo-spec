# 타꼬 타이밍 맞추기 연동 계약

- 상태: **2026-10-18 게임 담당자 전민규의 사용자 선택 반영**. 2026-10-16 FE 초안을 바탕으로 현재 FE 규칙과 기존 게임의 공통 처리 방식을 채택했다. 실제 FE 반영·테스트·배포·DB 등록 완료와는 구분한다.
- 공통 흐름: G03 시작 → 플레이 → G04 일괄 제출. 플레이 ID·토큰·재시도·결과 응답·보상·오류 은닉은 [색깔 게임 연동 계약](game-color-word-draft.md)의 2·5·6절과 같은 방식을 사용한다. 이 문서는 타꼬 타이밍에서 달라지는 부분만 적는다.

## 1. 게임 식별과 규칙 버전

| 항목 | 값 |
| --- | --- |
| `code` | `TAKKO_TIMING` |
| `ruleVersion` | `takko-timing-v1` |
| `generatorVersion` | `takko-timing-generator-v1` |

## 2. 플레이 규칙 — 2026-10-18 사용자 선택

금색 구간에 선 타꼬 위를 좌우로 오가는 이쑤시개를 구간 안에서 멈춰 꽂는다. 위치는 길 왼쪽 끝 0 ~ 오른쪽 끝 1로 본다.

- 구간 안이면 10점, 구간 가운데 30% 안이면 퍼펙트 20점.
- **한 번이라도 구간 밖에 꽂으면 끝난다.** 목숨·제한 시간은 없다.
- 성공 횟수 `n`에 따라 어려워진다.
  - 한쪽 끝에서 반대쪽까지 가는 시간: `max(650, 1600 - n × 60)`ms
  - 구간 폭: `max(0.09, 0.22 - n × 0.01)`
- 구간 가운데 위치: `min + r × (1 - 2 × min)`, `min = 0.08 + 폭 / 2`, `r`은 난수. 앞 판 가운데와의 거리가 폭보다 작으면 `1 - 가운데`로 옮긴다.
- 이쑤시개 위치: 움직인 시간 `t`에 대해 `p = (t / 왕복 반쪽 시간) mod 2`, `p ≤ 1`이면 `p`, 아니면 `2 - p`. 매 판 왼쪽 끝 0에서 출발한다.
- 판정: `|위치 - 가운데| ≤ 폭/2 × 0.3`이면 퍼펙트, `≤ 폭/2`이면 성공, 아니면 실패.
- 일시정지·탭 이동 시 자동 정지, 재개 카운트다운이 있다.

**최소 보상 점수: 50점.** 일반 성공 10점·퍼펙트 20점을 서버가 계산한다. 유효한 0점·50점 미만도 통계에 포함하되 보상은 없다. 50점 이상은 사용자·게임·서버 최초 확정 시각의 KST 날짜당 1장이다. 같은 판 재시도는 최초 결과를 보존한다.

변경 전에는 규칙·50점이 임시 제안이고 입력 상한·계산 경계가 미정이었다. 변경 후에는 담당자의 “다른 게임이랑 똑같이 하고 점수만 그 기준에 맞게” 지시에 따라 현재 규칙·50점과 아래 공통 제한·재시도 흐름을 채택했다. 주문 게임은 같은 날 별도로 선택한 [주문 계약](game-takko-order-draft.md)을 따른다.

## 3. 시작 — G03 (gameData)

```json
{
  "ruleVersion": "takko-timing-v1",
  "rules": {
    "points": 10,
    "perfectPoints": 20,
    "minimumRewardScore": 50
  },
  "gameData": {
    "generatorVersion": "takko-timing-generator-v1",
    "seed": 123456789
  }
}
```

- 판마다 구간 위치에 난수를 한 번 쓴다. 난수는 색깔 게임과 같은 xorshift32다.

## 4. 종료 — G04

구간 밖에 꽂아 끝났을 때 제출한다. 점수·성공 여부·구간 위치를 신뢰값으로 보내지 않는다.

```json
{
  "playToken": "example-opaque-token",
  "validationData": {
    "taps": [
      { "sequence": 1, "elapsedMs": 812 },
      { "sequence": 2, "elapsedMs": 1490 },
      { "sequence": 3, "elapsedMs": 233 }
    ]
  }
}
```

위 값은 형식 예시다. 예시 seed로 실제 계산한 값이 아니며, 공통 테스트 예제는 구현 시 고정한다.

| 필드 | 의미 |
| --- | --- |
| `sequence` | 1부터 연속된 판 번호 |
| `elapsedMs` | 그 판에서 이쑤시개가 실제로 움직인 시간(일시정지·카운트다운·결과 연출 제외), 내림한 정수 ms |

서버 판정:

1. 저장한 seed로 판마다 구간을 만들고, `elapsedMs`로 이쑤시개 위치를 계산해 판정한다.
2. 실패는 마지막 기록 하나뿐이어야 자연 종료다. 중간에 실패가 있거나 마지막이 성공이면 규칙 위반이다.
3. 점수는 서버 계산값이다.

한계: 제한 시간이 없고 위치가 시간으로 정해지므로, seed를 아는 프로그램은 매 판 퍼펙트가 되는 시간을 계산할 수 있다. 색깔 게임과 같은 한계이며 사람의 플레이를 증명하지 못한다.

## 5. 프론트 변경 사항

- `Math.random` 대신 G03 seed의 xorshift32로 구간 생성. 첫 판 구간도 G03 응답을 받은 뒤 만든다(지금은 화면을 열 때 만든다).
- **꽂은 순간의 시간으로 판정.** 지금은 마지막으로 그린 프레임의 위치로 판정해 서버 계산과 최대 한 프레임만큼 다를 수 있다. 누른 시각의 `elapsedMs`로 위치를 계산해 판정하고, `Math.floor`로 내림한 정수 ms로 **화면 판정과 제출을 모두** 수행한다. 소수 ms로 판정한 뒤 제출만 내림하지 않는다.
- 판별 `elapsedMs`를 모아 종료 시 한 번에 제출.

## 6. 입력 한도·판정 경계·재시도

- G04 전체 본문 최대 1MiB(1,048,576바이트), `taps` 최대 10,000개. 초과는 413 `GAME-008`이며 결과를 확정하지 않는다. 한도 도달을 별도 정상 종료로 추가하지 않는다.
- `taps`는 배열이고 각 항목의 `sequence`는 32bit 정수, `elapsedMs`는 64bit 정수다. 누락·타입 오류·다른 게임 입력(`answers`, `inputs`, `endTick`, `totalTicks`) 혼합은 400 `COMMON-005`다. 음수 시간·불연속 번호·빈 배열·첫 실패 이후 기록·성공으로 끝난 기록은 200 `INVALID`이며 통계·보상에 반영하지 않는다.
- G03에서 저장한 규칙·생성 버전·seed로 판정한다. 손상된 저장 설정은 사용자 입력의 INVALID로 확정하지 않고 공통500으로 처리한다.
- 위치와 경계는 위 2절의 double 연산 순서 그대로 계산한다. `distance <= width / 2 * 0.3`, 그 외 `distance <= width / 2` 순서이며 epsilon이나 소수점 반올림을 추가하지 않는다. 실제 기기 경과시간은 내림 정수 ms로 통일한다.
- 동일 playId·토큰·taps의 재제출은 최초 결과·점수·보상을 유지한다. JSON 공백·키 순서는 무관하고 판 번호·ms·배열 순서가 달라지면 기존409 `GAME-006`이다. 다른 게임 입력 모델로 이 플레이를 확정할 수 없다.
- ADMIN은 기존 계약대로 체험 시작만 허용하며 결과 제출은403 `GAME-007`이다. 결과 응답·202 PROCESSING·429 Retry-After·소유권 은닉은 기존 G04 계약을 재사용한다.
- 실제 서버 경과시간과 제출 시간의 대조는 기존 게임과 같은 후속 항목이며 이번에 추가하지 않는다. 시작 seed를 알고 시간을 계산할 수 있는 신뢰 한계는 유지한다.

### 양측에서 사용할 고정 예제

아래는 seed=1의 xorshift32와 현재 FE 모델의 연산식으로 만든 **참조 데이터**다. 테스트 성공 또는 FE와 Java 실행 결과가 일치했다는 보고가 아니다. 양측 테스트에서 같은 값을 검증해야 한다.

| 판 | 중심 | 폭 | sweepMs | 퍼펙트 elapsedMs | 일반성공 elapsedMs |
| --- | --- | --- | --- | --- | --- |
| 1 | 0.1900390291167423 | 0.22 | 1600 | 304 | 427 |
| 2 | 0.8050791202508845 | 0.21 | 1540 | 1240 | 1353 |
| 3 | 0.5744986255466937 | 0.2 | 1480 | 850 | 954 |

`taps`의 sequence를 1부터 붙였을 때 시간 배열 `[0]`→VALID 0점, `[304,1240,0]`→40점, `[304,1240,954,0]`→50점, `[304,1240,850,0]`→60점이다. `[2896,1840,954,0]`은 반사 이동을 포함한50점 예제다. 끝의0은 다음 판의 첫 실패다. `[304]`, `[0,304]`, `[]`는 INVALID다.

포함 경계 검증용으로 중심0.5·폭0.625·sweepMs1024를 사용하면 elapsedMs192/832는 일반성공,191/833은 실패,416/608은 퍼펙트,415/609는 일반성공이다. 이 구간은 계산 함수 경계를 확인하는 예제이며 위 seed1의 실제 첫 구간을 대체하지 않는다.
