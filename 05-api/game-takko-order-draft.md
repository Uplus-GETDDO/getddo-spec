# 타꼬 주문 연동 계약

- 상태: **2026-10-18 게임 담당자 전민규의 사용자 선택 반영**. “현재 FE 규칙 유지, 18점부터 하루 1장”을 선택했다. 2026-10-16 FE 초안을 채택한 것이며 실제 FE 변경·검증·배포·DB 등록 완료와 구분한다.
- 공통 흐름: G03 시작 → 플레이 → G04 일괄 제출. 플레이 ID·토큰·재시도·결과 응답·보상·오류 은닉은 [색깔 게임 연동 계약](game-color-word-draft.md)의 2·5·6절과 같은 방식을 사용한다. 이 문서는 타꼬 주문에서 달라지는 부분만 적는다.

## 1. 게임 식별과 규칙 버전

| 항목 | 값 |
| --- | --- |
| `code` | `TAKKO_ORDER` |
| `ruleVersion` | `takko-order-v1` |
| `generatorVersion` | `takko-order-generator-v1` |

## 2. 플레이 규칙 — 2026-10-18 사용자 선택

손님 주문(타코야끼 순서)을 잠깐 보여 준 뒤 가리고, 같은 순서로 내준다(순서 기억 게임).

- 메뉴는 4가지, 순서는 `scallion`(파), `cheese`(치즈), `shrimp`(새우), `nori`(김).
- 첫 주문 길이 3. 맞히면 길이 +1(최대 8), 틀리면 같은 길이의 새 주문.
- 맞힌 주문 1개당 **주문 길이만큼** 점수(3개짜리 3점, 4개짜리 4점…).
- 목숨 3개. 화면에서는 틀려도 주문 길이만큼 끝까지 고른 뒤 판정하고, 하나라도 순서가 다르면 목숨 1개를 잃는다. 목숨을 모두 잃으면 끝난다.
- 판정 전에는 마지막으로 고른 메뉴를 하나씩 지울 수 있다. 서버에는 지운 뒤의 최종 순서만 제출되므로 `picks` 계약은 바뀌지 않는다.
- 주문을 보여 주는 시간: `800 + 길이 × 600 + max(0, 길이 - 4) × 400`ms (3개 2.6초 · 4개 3.2초 · 5개 4.2초 · 8개 7.2초). 고르는 시간 제한은 없다.
- 보여 주는 시간·판정 시점·지우기는 화면 연출이며 서버가 검증하지 않는다. 서버 판정은 아래 4절의 `picks`만 본다.
- 주문 생성: 메뉴를 하나씩 난수로 뽑되, 같은 메뉴가 세 번 연달아 나오면 버리고 다시 뽑는다.

**최소 보상 점수: 18점.** 3·4·5·6개 주문을 성공하면18점이다. 유효한 미달·0점도 통계에 포함하고,18점 이상은 사용자·게임·서버 최초 확정 시각 KST 날짜당1장이다. JSON의 점수·정답 여부를 신뢰하지 않는다.

2026-10-21 FE 화면 변경: 틀려도 끝까지 고른 뒤 판정, 판정 전 지우기, 5개 이상 주문의 보여 주는 시간 연장. 서버 판정·점수·보상 기준은 그대로다.

변경 전에는 현재 규칙·18점이 참고값이었다. 변경 후에는 담당자가 현재 FE 규칙과18점 추천안을 명시적으로 선택했다. 기존 공통 시작·저장·통계·보상·입력 제한을 재사용한다.

## 3. 시작 — G03 (gameData)

```json
{
  "ruleVersion": "takko-order-v1",
  "rules": {
    "initialLives": 3,
    "startLength": 3,
    "maxLength": 8
  },
  "gameData": {
    "generatorVersion": "takko-order-generator-v1",
    "seed": 123456789
  }
}
```

- 메뉴 하나를 뽑을 때마다 난수를 한 번 쓴다(버리고 다시 뽑는 것도 포함). 난수는 색깔 게임과 같은 xorshift32다.
- 손님 얼굴 등 화면 꾸밈은 이 난수를 쓰지 않는다.

## 4. 종료 — G04

목숨을 모두 잃었을 때 제출한다. 점수·정답 여부·주문 내용을 신뢰값으로 보내지 않는다.

```json
{
  "playToken": "example-opaque-token",
  "validationData": {
    "rounds": [
      { "sequence": 1, "picks": ["cheese", "nori", "cheese"] },
      { "sequence": 2, "picks": ["shrimp", "scallion"] },
      { "sequence": 3, "picks": ["nori", "nori", "cheese", "shrimp"] }
    ]
  }
}
```

위 값은 형식 예시다. 예시 seed로 실제 계산한 값이 아니며, 공통 테스트 예제는 구현 시 고정한다.

| 필드 | 의미 |
| --- | --- |
| `sequence` | 1부터 연속된 주문 번호 |
| `picks` | 그 주문에서 고른 메뉴 순서. 맞히면 주문 전체, 틀리면 처음 틀린 메뉴까지 (화면에서 끝까지 골랐어도 처음 틀린 뒤의 메뉴는 보내지 않는다) |

서버 판정:

1. 저장한 seed로 주문을 차례로 만든다. 길이는 앞 결과(맞힘 +1 / 틀림 그대로)로 정한다.
2. `picks`가 주문과 같으면 맞힘, 마지막 하나만 다르고 앞이 모두 같으면 틀림이다. 그 밖의 꼴(주문보다 길다, 중간이 다르다)은 규칙 위반이다.
3. 세 번째 틀림이 마지막 기록이어야 자연 종료다.
4. 점수는 서버 계산값이다.

한계: seed를 아는 프로그램은 주문을 미리 알 수 있다. 화면 캡처로 외우는 것도 막지 못한다. 색깔 게임과 같은 한계다.

## 5. 프론트 변경 사항

- `Math.random` 대신 G03 seed의 xorshift32로 주문 생성. 첫 주문도 G03 응답 뒤에 만든다.
- 손님 얼굴 선택은 별도 난수로 분리.
- 주문별 `picks`를 모아 종료 시 한 번에 제출.
- (권장) 다른 게임처럼 일시정지·탭 이동 시 자동 정지 추가. 지금은 탭을 옮겨도 주문 보여 주기가 계속 흘러간다.

## 6. 입력 한도·결과·재시도

- 기존 게임과 같이 G04 전체 본문 최대1MiB(1,048,576바이트), `rounds` 최대10,000개다. 초과는413 `GAME-008`, 결과 미확정이다. 입력 한도 도달을 정상 종료로 바꾸지 않는다.
- 각 `sequence`는32bit 정수이고 `picks`는 위 메뉴 문자열의 배열이다. 누락·타입·알 수 없는 메뉴·다른 게임 입력(`answers`, `inputs`, `endTick`, `totalTicks`, `taps`) 혼합은400 `COMMON-005`다.
- 빈 배열·불연속 번호·빈 선택·주문보다 긴 선택·맞는 부분만 제출한 미완료·첫 오답 뒤 추가 선택·세 번째 실패 후 추가 주문·목숨 잔여는200 `INVALID`다. 통계·청구·보상에 반영하지 않는다.
- 같은 playId·토큰·원본 rounds는 최초 결과를 반환한다. JSON 공백·키 순서는 무관하고 주문 경계·번호·선택 배열이 바뀌면409 `GAME-006`이다. 다른 게임의 입력 모델로 이 판을 확정할 수 없다.
- ADMIN은 체험 시작만 가능하며 결과 제출은403 `GAME-007`이다. 202 PROCESSING·429 Retry-After·소유권 은닉·트랜잭션은 공통 게임 계약을 재사용한다.
- 주문 표시 시간이나 실제 서버 경과시간을 제출 기록만으로 검증하는 기능은 이번에 추가하지 않는다. 보여 주기·꾸밈 난수 분리·일시정지 안내는 FE 후속이며 이번 BE 변경으로 FE 구현까지 완료됐다고 판단하지 않는다.

### 공통 고정 예제

seed1에서 주문 길이를3→4→5→6→7→7→7로 호출했을 때 아래 주문이 나온다. 같은 메뉴 세 번의 재추출도 난수 흐름에 포함한다. **FE 연산식으로 만든 참조 데이터이며 FE/Java 실행 검증 성공을 뜻하지 않는다.**

| sequence | 주문 | 제출할 picks | 결과 |
| --- | --- | --- | --- |
| 1 | scallion,scallion,shrimp | 주문 전체 | +3 |
| 2 | scallion,shrimp,scallion,scallion | 주문 전체 | +4 |
| 3 | scallion,cheese,shrimp,shrimp,cheese | 주문 전체 | +5 |
| 4 | shrimp,scallion,scallion,nori,scallion,nori | 주문 전체 | +6 |
| 5 | scallion,nori,shrimp,nori,cheese,nori,scallion | cheese | 첫 실패 |
| 6 | cheese,shrimp,scallion,scallion,shrimp,scallion,nori | scallion | 두 번째 실패 |
| 7 | scallion,shrimp,cheese,scallion,nori,cheese,scallion | cheese | 세 번째 실패·VALID18점 |

실패 주문을 끝까지 완성해 보내지 않고 첫 오답에서 기록을 끝낸다. 예를 들어 첫 주문에 `[cheese]`는 정상 오답이고 `[cheese,scallion]`은 첫 오답 후 선택이 있어 INVALID다. `[scallion]`은 미완료로 INVALID다.
