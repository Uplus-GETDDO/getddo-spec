# ADR-027: 응모 요청 반복 초과의 자동 일시 차단과 이력 조회

- 상태: 제안 — Codex 작성, 담당자 문서 확인 전
- 작성자 / 날짜: Codex / 2026-10-21
- 검토자: 사용자와 정책·조회 필드 방향 합의. ADR 문서 자체 검토는 대기
- 관련 작업 기록 / PR: [GD-141 스펙 정리](../04-worklogs/2026-10-21-gd141-entry-blocking.md) / PR 없음
- 대체한 ADR / 대체된 ADR: ADR-018의 정상 응모 유지·추첨 제외 폐지 원칙은 유지하고 응모 요청 일시 차단 범위를 추가 구체화

## 배경

기존 Redis 기반 일반 요청 제한을 이어받아 반복 초과를 사용자별로 일시 차단하고 관리자 화면에서 이력을 조회하려는 요구가 있었다. AR01/AR02가 구현 전 제안이어서 FE가 목록·상세 계약을 고정할 수 없었다.

## 결정과 이유

- 변경 전에는 일반 요청 제한이 구현되어 있고 신규 자동 차단의 운영 기준·조회 DTO는 후속 확인이었다.
- 변경 후의 정책 원본은 [응모 규칙](../02-domain/entry.md#응모-요청-반복-초과에-따른-일시-차단--gd-141), 공개 계약 원본은 [AR01/AR02](../05-api/abuse.md)다. 이 ADR에 수치·DTO를 중복 정의하지 않는다.
- 자동 차단은 제한 반복에 따른 일시 조치로 기록하며 관리자 부정 확정이나 정상 응모의 추첨 제외와 구분한다.

## 검토한 대안

- 사용자는 전체 요청 수 대신 일반 제한으로 거절된 요청만 집계하는 방식을 선택했다.
- 기존 한도의 2배인 거절 횟수 제안 대신 기존 한도와 같은 횟수를 초기값으로 선택했다.
- 차단 중 종료 시간 연장은 하지 않기로 선택했다. 별도 성능·운영 실험은 하지 않았다.

## 영향과 재검토 조건

- FE는 조회 필드·라벨·필터·차단 시각 표시를 계약에 맞추며 배포 여부는 별도로 확인한다.
- 기존 검토 데이터 삭제를 승인한 결정이 아니다. 기존 FK·검토 이력·게임 사후 처리와의 호환성은 새 마이그레이션 전에 확인한다.
- Redis 장애 시 요청 통과, Redis 자체 유실 시 미저장 이력 유실 가능성을 허용한 초기 범위다. 보존 보장이 필요해지면 재검토한다.
- evidence 세부 필드명·오류 번호·실제 구현·배포는 명시된 후속으로 구분한다. 문서 작성만으로 GD-141이나 구현 티켓을 완료 처리하지 않는다.
