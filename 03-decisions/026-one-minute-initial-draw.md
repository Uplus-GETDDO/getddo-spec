# ADR-026: 최초 자동 추첨 대기 시간을 1분으로 단축

- 상태: 제안
- 작성자 / 날짜: Codex / 2026-10-21
- 검토자: 사용자 정책 변경 요청 — 문서 담당자 검토 대기
- 관련 작업: [GD-268](https://ureca4.atlassian.net/browse/GD-268) / [작업 기록](../04-worklogs/2026-10-21-one-minute-initial-draw.md)
- 대체 범위: ADR-009·ADR-018·ADR-019·ADR-022에 남아 있는 마감 후 5분 일정에 한정한다. 관리자 수동 공개·당첨 취소·재추첨·이력 보존 결정은 유지한다.

## 배경

사용자가 최초 자동 추첨을 이벤트 마감 후 5분이 아닌 1분부터 실행하도록 요청했다. 성능 실험의 결과로 대기 시간을 선택한 것은 아니다.

## 결정

- 변경 전: 응모 마감 후 5분부터 최초 자동 추첨을 실행했다.
- 변경 후: 응모 마감 후 1분부터 최초 자동 추첨의 대상이 된다. 실제 실행은 확인 주기·순차 처리·복구 상황에 따라 늦을 수 있다.
- 시간 기준의 원본은 [추첨 규칙](../02-domain/drawing.md#2026-10-21-최초-자동-추첨-대기-시간-단축--gd-268)이다.
- 자동 추첨 이후 관리자 검토·개별 당첨 취소·빈 자리 재추첨·수동 발표를 유지한다. 응모 마감 검증·잠금·중복 방지·복구 기준을 시간 여유로 대체하지 않는다.

## 영향

- 백엔드: 대상 조회·잠금 후 재검사·확정 실행과 취소·발표의 최소 시각 검사, `drawScheduledAt` 계산을 함께 맞춘다. 기존 확정 실행·결과·공개 이력과 DB 마이그레이션을 소급 변경하지 않는다.
- 프론트엔드: 관리자 일정은 서버 `drawScheduledAt`을 따른다. 하드코딩한 5분 안내가 있으면 정렬해야 한다. 사용자에게 고정 발표 시각이나 카운트다운을 추가하지 않는다.
- 알림: 실제 공개에 연결된 생성·발송을 유지한다. 알림 담당 문서는 추첨 대기 시간 참조만 1분으로 맞추며 알림 API·DTO·발송 구현은 변경하지 않는다.
- 스케줄러 주기와 처리 건수, 실행 임대·재시도 제한은 이번 결정의 변경 대상이 아니다.

## 검증과 적용

1분 직전·정각·직후, 취소·삭제 상태와 관리자 일정 응답을 검증한다. 정책 문서 반영과 백엔드 PR 병합·배포·프론트엔드 적용 완료를 구분한다.
